# 自动化平台持续改进路线图

目标是货源 → 事实标准化 → 英阿内容 → 商品图/视频 → 核验 → 人工批准 →
noon 提交与回读 → 有效可售 → 订单履约与结算的可追踪闭环。
开发自动化与经营自动化分开验收；店铺/API/模型权限缺失时保留 HOLD。

| 优先级 | 工作 | 完成证据 |
| --- | --- | --- |
| P0 | 修复首次全量测试发现的42项失败/报错；逐项区分缺陷与旧契约测试 | 不跳过测试；全部通过，含实际服务器重启和浏览器启动 |
| P0 | Linux/云端环境与 CI 首次运行 | setup 成功、依赖检查、云端运行日志和提交 SHA |
| P1 | 调度器可控时间、事件唤醒与到期扫描 | 假时钟覆盖等待/批准/配置变更；关闭重开不重复执行 |
| P1 | 外部调用幂等与不确定回执对账 | 发送前/后断电、超时、限流、取消、失败逐项验收 |
| P1 | 5000行货源投递与跨批去重、身份矛盾隔离 | 跨500行边界、断点复用、0/空白语义、错误行可下载 |
| P1 | 1万SKU性能与分页契约 | 固定数据集；记录首屏/扫描/内存/DB查询耗时；不整库反复回传 |
| P1 | 图片生成与比较协议、参考资料完整性 | 合成协议+真实商品小样；原图不篡改，错图不放行 |
| P1 | 候选图→图片托管→人工审核→提交回读闭环 | 链接公开可读、审核绑定版本、错误不自动重发 |
| P2 | 调度频率、并发和日预算的可观测控制 | 队列年龄、重试原因、调用账本与预算预警可审计 |
| P2 | 周期备份/保留规则/异地恢复演练 | 明确RPO/RTO，恢复后队列暂停并核对外部状态 |
| P2 | 后台业务服务部署 | 持久化、登录权限、TLS、监控；真实运行验收 |
| P2 | 价格库存同步与有效可售回读 | 经授权小样；live_status 与 offer_issues 独立读取 |
| P3 | 订单拉取、库存预占、采购/履约、退货与结算对账 | 真实单据核对；采购付款仍需具体授权 |

初始重点：稳固已有平台，不重复造一个单独演示版。每轮推进一个最重要且可验证的项目，
在验证记录保留问题、复现、改动、测试和下一步。架构升级依照容量证据分阶段实施。
