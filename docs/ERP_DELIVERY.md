# Noon ERP 本地业务交付说明

2026-10-03，集成分支 `codex/erp-delivery`。用户要求两小时内推进完整平台；
本轮GPT-6.1 Sol medium 子任务分轮并行开发，四轮交付21个模块，复用已有商品、
运营、库存、财务、采集和恢复服务。软件验收与真实平台经营分开记录。

## 本轮可使用的功能

| 页面 | 可执行的业务 | 明确边界 |
| --- | --- | --- |
| 订单批量导入 | CSV/JSON最多5000行；按店铺订单号分组，SKU/金额/日期预检，确认建单与回执防重 | 标准本地模板；不拉取真实Noon订单，不自动占库 |
| SPU与规格组 | 1–3个规格轴、每组100SKU、跨组排他、规格组合唯一、版本复核 | 本地分组；Noon父子变体发布仍待接入 |
| 商品批量编辑 | 跨页500件，填空/明确替换，逐字段前后预览，原子保存 | 0为已知值；修改后重新审核，在途任务阻断；不生成或推测事实 |
| 批量拣货发货 | 100订单累计缺货预检、批量占库、SKU拣货CSV、运单核对、批量出库 | 原订单不拆合；本地拣货单不是承运商电子面单或平台发货回执 |
| 采购订单关联 | SKU需求分配到既有采购；数量守恒、版本核对、需求缺口与关联解除 | 不自动采购、付款或把关联当作已收货；收货/取消后需复核 |
| 售后与退款 | 退货登记/验收、可用/隔离/报废、隔离释放、退款与赔付费用 | 与既有退货计数一致；本地费用登记不发起平台退款或实际付款 |
| 结算文件核对 | 500行标准CSV/JSON、订单映射、重复/冲突隔离、原币分组、销售差额、确认记账 | 未支持所有Noon原始结算格式；导入不登记现金流 |
| 银行流水核对 | 标准流水导入、候选建议、人工选择、分次核销、回执与安全CSV | 导入与付款核销分两次确认；不连接银行或转账；金额取服务器原始行 |
| 经营分析 | 日期/店铺/仓库筛选、原币订单金额、发货/退货、采购、库存、已核贡献与缺口 | 库存估值基于参考成本；贡献、差额与估值都不能当净利润 |
| 周期采集 | 授权来源规则、间隔与账号版本、在途不堆积、异常暂停/核对恢复 | 只采集候选，不自动入库；应用关闭时不执行，不补跑积压 |
| 周期备份 | 本地完整ZIP、确认启用、保留1–30份、失败与中断历史 | 只清理由规则登记且校验一致的旧副本；手动/回退/未登记文件保留 |
| 异常中心 | 8类本地异常、50项分页、来源证据、确认已阅、最多7天后提醒 | 确认已阅不解决业务异常；来源变化重新提醒；不发送外部消息 |
| 国内网页采集 | 1688/淘宝/拼多多主动浏览器采集、资料包预检、确认候选、独立确认商品入库 | 当前页公开字段；不登录、不读取会话；无真实平台/全页面模板验收，缺规格保持待补；可按独立依据人工校对并保留原值 |
| 批量库存盘点 | 500SKU实盘数、依据、差量预览、整批确认、并发流水校验与回执 | 良品在库含占用，不含隔离/在途；空白不是0，不直接覆盖库存 |
| 物流包装与交接 | 已发货单实测重量尺寸、箱号、包装/SKU/交接CSV、来源变更复核、人工交接依据 | 本地包装清单；不调用承运商、生成电子面单、重新出库或标记客户签收 |
| 价格方案预检 | 成本/汇率依据、含税/未含税口径、费用预留、保本价、跌价保护、建议价草稿与复核 | 预计贡献不是净利润；缺参数保持未知；sendable=false，不发送Noon或改商品成本 |
| 广告归因分析 | 标准报告导入、重复/冲突版本、原币与归因层级汇总、CTR/CPC/ACOS/ROAS、筛选与安全CSV | 不连接广告账号/预算；归因销售不记财务收入；零分母未知 |
| 导入字段模板 | 命名列对应与明确固定币种，订单/结算/银行复用，原值/转换值/问题逐行可见 | 不猜金额/日期，不转换币种；修改/撤销模板使旧文件预检失效 |
| 供应商询价比较 | 100SKU×50供应商，本地询价需求、报价依据/起订量/交期/有效期、分币种比较、来源漂移复核 | 空白报价保持草稿；不换币比较，不发送询价消息、采购单或付款 |
| 汇率档案 | 明确币种对/乘除方向/适用日期/依据、不可变历史版本、精确版本换算与三种舍入、安全CSV | 手录资料；撤销后所有版本停止换算；不自动修改账务、价格或下载汇率 |
| 库存补货建议 | 每仓SKU最低/目标/提前天数、可用库存与采购未收依据、建议量、版本确认、筛选与CSV | 未建库存账与未知参数不按0；采购关联不重复加供给；不自动采购、预测销量或推算到货日 |


## 建议的工作顺序

1. 在“业务档案”建立供应商、店铺和仓库；先登记1688/淘宝/拼多多来源，使用国内网页采集或文件导入商品事实。
   浏览器扩展安装、允许的商品地址及采集边界见[国内采集说明](DOMESTIC_CAPTURE.md)。
2. 核对规格组、批量补齐资料，继续现有双语/素材/审核与刊登流程。
3. 订单按标准模板导入，核对需求，在询价比较中核对报价、在补货建议中核对数量，再建立并关联采购，收货后做批量拣货与发货。
4. 退货先登记与验收；隔离数量复核后再恢复可用库存；退款费用和实际付款分开。
5. 结算文件登记原币收入费用；银行流水核对后才核销余额；汇率档案保存转换依据但不追溯改账；在分析页核查未录成本。
6. 按需要确认启用周期采集和备份，在异常中心处理当前来源异常。

所有业务操作使用当前版本和持久请求编号；预检后的订单、商品、库存、凭证变化会
使预览失效。相同请求返回原回执，不重复建单、扣库存或计账。预检和提醒操作不自动
修改业务事实。退款与赔付共同受可核对订单原币金额上限约束；跨币种资料不足时暂停。

## 启动与备份

```bash
bash scripts/setup.sh
.venv/bin/python workbench/server.py --data /tmp/noonai-preview --port 8791
```

浏览器打开 `http://127.0.0.1:8791`。上面的临时目录用于试用与测试；实际经营应使用
固定资料目录并做好备份。服务只监听本机，写操作需要会话令牌。没有公开部署或团队
访问功能；不要将这个本地服务直接暴露到网络。

恢复旧备份时按模块真实定义补表和索引；已有结构被改写的备份拒绝。
恢复会暂停来源采集/自动任务、停用来源账号/模型和两个周期规则、撤销商品审核。
凭证不包含在ZIP中，恢复后先核对权限和真实平台状态，再明确启用。
