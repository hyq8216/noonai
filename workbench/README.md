## 服务配置

复制 `.env.example` 为 `.env`，填写后重启。不要将密钥放入商品备注、CSV或浏览器地址。

- `TEXT_API_BASE`：兼容Chat Completions的HTTPS地址，默认 `https://api.openai.com/v1`。
- `TEXT_DAILY_LIMIT`：每日翻译任务上限，默认50，按UTC日计数；排队和失败任务均计入。
- `TEXT_API_KEY`、`TEXT_MODEL`：用户选择的文字服务。必须支持JSON对象输出。
- `NOON_CREDENTIALS_FILE`：官方服务账号JSON文件的绝对路径，包含 `key_id`、`private_key`、`project_code`。
- `NOON_ENABLE_CONTENT_SUBMIT`：默认0。完成账号和类目联调后才设为1。仅开放内容提交，不开放报价或库存写入。

开发中：在“批量刊登与结果”可选择最多500件已审核商品，预检后排队提交 noon 商品内容；逐件保留任务状态，并可取消尚未发送的任务。提交超时或回执不明时需先回查平台，不能直接重发同版本。此入口尚未测试、打包或通过真实店铺验证；没有店铺时只显示阻断原因。

## 本地审核与平台状态

审核先检查来源、供应商、规格、品牌、类目、英阿内容、图片使用依据、实际照片、采购成本、可供数量、模式、供货核对时间及人工核对项。

供货核对24小时有效是本地试运行规则，不是平台规则。审核关联具体内容版本；任何修改均撤销审核。首版图像质量由人工核对，不会因为尺寸达标就自动宣称商品照片合规。

提交返回HTTP 200不代表成功。代码保留 `sku_parent` 并读取 `status.status_id`，内容有问题时任务为需处理；后续通过GetContent回查。即便内容审核通过，页面仍不会显示“已上架”或“可售已确认”。

## 财务与对账（0.7）

1. 先建立本地业务单据，再按结算单、采购成本或费用凭证登记财务条目。支持CNY/SAR/USD/AED；填写原币金额、1单位原币折合多少人民币、确认日期、全局唯一凭证行编号和来源依据。CNY汇率必须为1。源订单售价不会自动成为卖家收入。
2. 直接关联订单的条目全额归属该订单。关联采购单或独立的费用可分摊给多个订单，允许剩余待分摊，合计不能超过原币金额。成本只登记一次；共享费用使用分摊，避免重复建账。
3. 实际到账/付款时进入条目登记，允许分次结清；同币种原币金额逐笔核销，保留收付款当时汇率和依据。差额作为已实现汇差单独显示，不重复扣订单成本。实际收付款为本地记录，不会发起银行交易。暂不支持预付款及平台净额扣费的自动核销。
4. 录错时先撤销有效收付款，再作废条目并用新的凭证行编号重新登记；旧记录和原因保留。没有物理删除。
5. 签收订单登记收入和成本后，逐项确认收入、成本完整性和退款情况并写明依据，才能标记已核对贡献。增加退款/费用、收付款、重新分摊或订单退货后，原核对失效。

汇总是凭证登记差额，不是期间净利润；采购中可能含未售库存。订单贡献未含未录入项目及汇差，也不等同法定利润。未结余额按原币分开展示。CSV导出同时保留条目、收付款及作废记录，可能被表格软件当作公式的文本已经转义。

## 调拨与补货（0.8）

「调拨与补货」连接现有库存台账、采购收货和待处理订单。

- 调拨：先建调出仓→调入仓计划；实际发出后填写出库依据，此时只扣来源仓，货物在途；目的仓按本次实际验收数量分批入库。不能移走已被订单占用的库存，建单本身不预占库存。未调出可以取消；已调出不可直接取消，异常短少/损坏/退回的专用流程仍待开发。
- 规则：按商品/仓设置安全库存、目标库存、供应商、参考单价和报价依据，可修改或暂停。参考单价不是实时供应商报价。起订量和包装倍数均须正整数；目标不低于安全量。
- 建议：计入本地采购待收量、调拨在途、订单占用以及尚未占用的订单需求。创建采购单或验收到货后会重新计算；同一订单由待处理变成已占用时不会重复扣需求。被取消的采购余量不再计入在途。
- 采购：选中建议，核对参考价/数量/供应商后生成本地采购单；自动按供应商与到仓分组，随后去「采购收货」处理。不会向1688下单或自动付款。旧建议因库存、需求或规则变化会被拒绝，必须刷新后再确认。

只有设置且启用规则的商品参与补货；没有规则不等于库存充足。在途未按到货日期排序，本版没有承诺库存可售计算，不能把在途数量当作可立即发货数量。

## 0.9 备份与恢复

1. 在「备份与恢复」点击「创建并校验备份」。文件先保存在资料目录的 `recovery/archives`；校验完成后点击「下载 ZIP」保存到另一个位置。建议另存外置磁盘，留在同一块磁盘不是异地备份。
2. 恢复时选择本软件创建的ZIP，点击「检查文件和预览内容」，核对备份时间和商品/单据/媒体数量。普通商品导出包不能当完整备份恢复。
3. 确认替换资料后「安排下次启动恢复」。正在执行的商品、模型或媒体任务会阻止安排；可以先等其完成，或在相应队列暂停。安排成功后当前业务写入锁定，退出应用再重新打开即可开始恢复。取消恢复也不会自动恢复队列。
4. 软件先保存恢复前的回退备份，再替换资料。恢复成功可从页面下载该回退包；如需撤销恢复，用同一检查与恢复流程导入回退包。切换中断会在下次启动时先回滚，未通过检查时原资料不替换。
5. 恢复后的自动化、媒体和视觉队列保持暂停，模型配置停用，商品上架审核重置。请核对实际库存、订单、供应商和noon已执行结果，再启用模型/队列与重新审核，避免旧记录导致重复操作。

备份内容包括业务数据库所有表，以及当前/历史商品版本和媒体库引用的原图、成品与预览。排除credentials、.env、Codex登录、运行日志和临时工作文件；在另一台Mac上须自行配置连接。恢复保留当前机器的凭证，不代表这些凭证已与恢复的店铺/服务配置匹配。恢复的是本地时间点快照，不会撤销外部付款、发货和平台提交。

限制：仅支持同结构备份（不支持任意旧版本迁移）；压缩ZIP≤2GB、展开数据≤8GB、文件≤10万个，上限容量未实测。备份未加密，含经营资料。当前保留所有历史ZIP、导入缓存和原始回退目录，无自动清理、周期备份、云盘同步或多人协作。备份目录只对当前系统用户开放。
